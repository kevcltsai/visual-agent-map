## Claim
One statement that can be refuted, with the subject, the conditions and the direction stated. No reasons or evidence here.

## Current judgment
Keep only one: untested, leaning support, leaning against or refuted, with a short reason and what is missing. No weak/medium/strong rating (the Strength label has it). This takes precedence over the earlier rule for inconsistencies: list one only; on change rewrite it, log "from X to Y: reason".

## If true we would see
Concrete predictions that can be checked, one per line.

## What would refute it
Counter-conditions written in advance: which result would mean the claim fails.

## How to test
What data to look for, and what comparison or experiment to run.

## Evidence table
A four-column Markdown table whose header row is written exactly as `| Evidence | Supports or refutes | Strength | Linked topic |`, one row per piece of evidence, each with its source. Write linked topics only here, as topic links; do not restate the supporting and refuting content elsewhere.

## Sources
Only the source list, which is added to the end of this section automatically; do not restate the body.

## Update log
Add only one line saying what this update changed.
