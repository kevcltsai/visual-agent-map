The detail is a knowledge page for a beginner, rendered in Obsidian. It has two parts: first a connected narrative that draws the reader into the topic, then the content sorted into the categories below.

Opening (lead-in): 2–4 flowing paragraphs with no heading at all, in this order: why the topic is worth learning and how it relates to the reader, then the core concepts in plain language (introduce a technical term only when needed and explain it right away), then one worked example followed from start to finish with real numbers or steps. A reader who reads only this part should already understand the gist.

Body: after the lead-in, use exactly these six level-three headings (###), with the heading text copied exactly and in this fixed order: ### Core conclusions, ### Background and mechanism, ### Disagreements and limits, ### Open questions to check, ### Sources, ### Update log. Leave out a whole category that has no reliable material (no heading, and never write "No new content this time"; this rule overrides the later formatting rule that says to write 'No new content this time' in sections with nothing to say). In the core conclusions, answer the question in the first sentence, then give 2–4 reasons, and do not repeat sentences the lead-in already said. ### Update log gets only one line saying what this page covers.

Closing: put common misconceptions in the category where they fit best, as one short `> [!warning]` callout in the form "beginners often think ..., but actually ...". Just before "### Update log" (that is, above it) add a short block led by bold "**Self-check**" (no heading), with 2–3 questions the reader can use to test their understanding, optionally with a one-line hint.

## Core conclusions
The first sentence answers the topic's question directly, then 2–4 reasons, each one sentence of conclusion plus one sentence of reason. No background here.

## Background and mechanism
The concepts, data and workings needed to understand the conclusions; do not repeat the core conclusions or the disagreements.

## Disagreements and limits
Where the evidence is contested, counterexamples, when the conclusions apply, and what this research did not cover; write only limits if nothing is contested.

## Open questions to check
Questions not yet verified that are worth opening as subtopics; write each as a question that can be researched.

## Sources
Mark sources with footnotes in the body; this section holds only the source list, which is added to the end of this section automatically, without restating the body.

## Update log
Add only one line saying what this update changed.
