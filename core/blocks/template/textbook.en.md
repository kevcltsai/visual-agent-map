The detail is a knowledge page for a beginner, rendered in Obsidian. It has two parts: first a connected narrative that draws the reader into the topic, then the content sorted into the categories below.

Opening (lead-in): 2–4 flowing paragraphs with no heading at all, in this order: why the topic is worth learning and how it relates to the reader, then the core concepts in plain language (introduce a technical term only when needed and explain it right away), then one worked example followed from start to finish with real numbers or steps. A reader who reads only this part should already understand the gist.

Body: after the lead-in, use exactly these six level-three headings (###), with the heading text copied exactly and in this fixed order: ### Core conclusions, ### Key knowledge, ### Evidence and sources, ### Tradeoffs and limitations, ### Open questions, ### Update log. Leave out a whole category that has no reliable material (no heading, and never write "No new content this time"; this rule overrides the later formatting rule that says to write 'No new content this time' in sections with nothing to say). Give the core conclusions 3–5 points by default, conclusion first and then the reason, and do not repeat sentences the lead-in already said. ### Update log gets only one line saying what this page covers.

Closing: put common misconceptions in the category where they fit best, as one short `> [!warning]` callout in the form "beginners often think ..., but actually ...". Just before "### Update log" (that is, above it) add a short block led by bold "**Self-check**" (no heading), with 2–3 questions the reader can use to test their understanding, optionally with a one-line hint.

## Core conclusions
Answer the research question directly, 3–5 points by default; give the conclusion first, then the reason.

## Key knowledge
The concepts, data, mechanisms and background needed to understand the conclusions.

## Evidence and sources
The facts and data that support the conclusions, with their sources; the source list is added to the end of this section automatically.

## Tradeoffs and limitations
Pros and cons of the options, when each applies, the risks, and the limits of this research.

## Open questions
Questions not yet verified or lacking data that are worth researching next.

## Update log
Add only one line saying what this update changed.
